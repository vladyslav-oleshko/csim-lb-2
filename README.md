Перед безпосереднім додаванням затребуваних змін я маю внести деякі візуальні правки. to adjust-chlorophyll
  ;; If the temperature is low, then reduce the chlorophyll
  if current-temperature < 15 [
    set chlorophyll chlorophyll - (.5 * (15 - current-temperature))
  ]

Далі приступаємо до безпосередньо основного завдання лабораторної роботи за вказаним варіантом. Починаю з налаштування циклів дня та ночі. Визначаю новий внутрішній параметр `day-length` як глобальну змінну та встановлюю значення 20 (у функції `setup`). За вибором цього числа не стоїть специфічних розрахунків, лише хочу спробувати почати з нього, а пізніше за потреби змінити.

<pre>day-length ;; length of model day in ticks</pre>
<pre>set day-length 20</pre>

Наступним очевидним логічним кроком є створення нової функції, де буде описана зміна дня та ночі з використання створеного параметру. Назву її `update-daylight`.

<pre>
;; update-daylight: calculates daylight duration based on daytime (tick)
to update-daylight
  ;; 0 = morning, 90 - noon, 180 - evening (sunset), 180-360 - night.
  let phase 360 * (ticks mod day-length) / day-length
  ;; during day sun intensity changes by sinus, at night equals 0
  set current-sun max (list 0 (max-sun-intensity * sin phase))
end
</pre>

`ticks mod day-length` - повертає остачу від ділення поточного номера такту (tick) на тривалість доби (day-length, 20), що дозволяє отримати умовну "годину" дня від 0 до 19. Після ділимо на `/day-length` і таким чином отримуємо дріб від 0 до 1, яке потім будемо множити на кут від 0 до 360 градусів (sin у NetLogo працює з градусами). `let phase` - оголошуємо локальну змінну, в яку буде записано результат цієї операції.
Далі `max-sun-intensity * sin phase` - пікову сонячну інтенсивність множимо на синус фази (нову локальну змінну). У першій половині доби синус дорівнює буде від 0 до 180 градусів, у піку 90 (набирає до 90 макс, спадає з 90 до 0, сумарно 180). Відповідно це значення помножене на пікову інтенсивність і дасть нам значення поточної сонячної активності на такті.
`max (list 0 ...)` - усі від'ємні значення скидуємо до 0, отримуючи "ніч". У NetLogo max приймає список (масив), тому потрібно ще використати list, щоб покласти ці значення туди.

Врешті, викликаємо нову функцію у стартовій процедурі `go`.

Наступним етапом є налаштування зміни температури, але вже зараз можна провести міні-спостереження, адже з робочою симуляцією дня та ночі листя стало отримувати менше бонусів до прикріпленості і має опадати швидше. У першій лабораторній роботі, у першому дослідженні листя опадало за 77 тактів при силі вітру 5. Використовуючи всі ті самі стартові параметри, але з новою функцією, цей показник впав до ~58 тактів у середньому.

Далі додадю зміну температури. Одразу скажу, що хочу зробити зміну температури наближеною до реальності, де стає тепліше не одразу з появою сонця, а дещо пізніше, коли прогрівається повітря. Отже, роблю все за наступною послідовністю.

У `globals` додаю `temp-amplitude` (амплітуда добових коливань температури при максимальній інтенсивності сонця) та `temp-lag` (затримка у зміні температури).

<pre>
  ;; globals
  temp-amplitude
  temp-lag
  ;; setup
  set temp-amplitude 10
  set temp-lag 45
</pre>

У функції `setup` задаємо значення. Для амплітуди - 10, що на практиці означає коливання на +-10 градусів за інтенсивності сонця 100%. Наприклад, за інтенсивності 50% - +-5 градусів. Це теж певного роду симуляція реальності, адже вдень температури коливаються значно сильніше за ніч. Для затримки (`temp-lag`) обрав значення 45, бо використовуватиметься під час обчислень в градусах. 45 градусів це 1/8 від умовної доби - це і є "лаг" перед зміною.

Далі необхідно переписати раніше створену функцію `update-daylight`. Оскільки вона тепер рахує не лише інтенсивність сонця, але й зміну температури, то логічно перейметувати її, то ж називаю `update-day-cycle` та додаю нові розрахунки. Змінена функція виглядає наступним чином (коментарі частково прибрані).

<pre>
to update-day-cycle
  let phase 360 * (ticks mod day-length) / day-length

  set current-sun max (list 0 (max-sun-intensity * sin phase))

  ;; calc amplitude
  let amplitude temp-amplitude * max-sun-intensity / 100
  ;; set current temperature base on amplitude and other params
  set current-temperature average-temperature + amplitude * sin (phase - temp-lag)
end
</pre>

Нові розрахунки частково схожі з наявними, але для температури відсутнє обрізання до нуля (`max (list 0 ...)`), бо вона може бути від'ємною навідмінно від інтенсивності освітлення. Також важливо операцію `(phase - temp-lag)` огорнути в дужки, щоб вона виконалась раніше за викликання `sin` та множення на нову локальну змінну `amplitude`. Тобто вираховуємо лаг/затримку із фази перед усім іншим.

Останнім кроком є оновлення `go`, де необхідно прибрати заглушку `set current-temperature average-temperature` (бо вони тепер розраховуються динамічно) та врешті лишити лише `update-day-cycle`.
